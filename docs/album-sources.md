# 专辑音源与曲目规格

音乐库仍按专辑名、专辑艺术家组织专辑。专辑详情在完整曲目集合上划分
音源副本，默认只展示一份；歌曲、艺术家下的歌曲及目录列表保留全部曲目。
音源分组不更改曲目 ID、收藏或歌单关联，也不删除文件。

## 分组规则

- 普通曲目按规范化目录与文件格式分组；相同格式在不同目录的副本分别保留。
- CUE 按 CUE 文件身份分组，一份多 FILE CUE 即使引用不同目录、不同格式也
  保持完整；同目录内的独立 MP3 和 WAV+CUE 分开。
- CD1 / Disc 1 / Disk 1 等明确碟目录，只有碟号标签与目录编号一致时才允许
  合为父目录中的多碟音源。CUE 还要求去掉碟号后的文件名一致；同碟号存在
  多个目录副本时不猜测配对，保留独立来源。
- 不凭曲名或时长去重，不假定较高采样率代表更好的母带。无法区分的同目录、
  同格式文件仍保留在一起；音频指纹去重和手动版本管理不在本次实现范围内。

首次打开优先展示曲目数最多的一份，同数按稳定来源键排序。选择后保存到应用
设置，最多保留 512 个专辑的选择；来源移除后回退到现存来源。点击歌曲的专辑
链接时会定位到该歌曲所属音源。来源 ID 不代替曲目 ID。

专辑先加载完整集合再展示，避免分页中途改变默认来源。搜索只筛选当前音源，
没有匹配时展示空结果，不切换到其它音源。切换来源和搜索不会改变已有队列；
播放全部才对可见集合建立队列快照，单击搜索结果继续沿用保留队列的行为。

## 音频信息

CatalogItem.audio 携带缓存的格式、编码、采样率、位深、PCM 类型、声道、
可选码率，以及来源目录和 CUE 区间。后端每页批量查询文件信息，不在滚动、
悬停或详情打开时重新探测音频文件；同一 CUE 音频文件复用缓存。

宽列表恢复可排序、可调整宽度的格式列；窄列表在标题下方显示格式。
点击格式或菜单中的“曲目信息”可查看规格及可复制的路径和 CUE 采样帧区间。
专辑来源栏显示音频规格；播放栏和播放详情的紧凑标签只显示格式，不展示采样率、位深或码率。
不再仅凭 FLAC/WAV 扩展名显示 HI-RES。

技术属性统一由有读取预算的 Lofty 探测模块补充，普通扫描即可升级旧缓存，无需重建。
估算值显示“约”，平均码率在详情明确标注；有损编码未知时显示“未知”，无损/PCM 未知时隐藏码率项。
CUE 标为源文件平均码率，NCM 保留容器名并显示内部编码。码率不参与音源身份或混合规格判定。
读取预算、缓存重试和格式范围见 [音频技术属性](audio-properties.md)。

## 验证

- Rust 测试确认从缓存读取音频属性，不需要源文件存在。
- Flutter 测试覆盖普通副本、MP3/CUE、多 FILE、多碟、设置持久化、来源删除
  回退、限定音源搜索，以及显式播放前后队列边界。
- 对当前曲库 Magical Mirai 2016 专辑作只读导出，确认 20 条记录划分为
  10 首 MP3 和 10 首 WAV+CUE。
